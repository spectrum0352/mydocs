Internal vs. External Threats


Internal threats come from people or weaknesses within your organization:
•	Employees: They can cause harm intentionally (sabotage, data theft, fraud) or unintentionally (clicking phishing links, deleting files).
•	Contractors: With access to sensitive information, they can pose a threat if not properly vetted or supervised.
•	Insider threats: Employees or contractors with authorized access can be a risk, whether intentional or unintentional.
•	System vulnerabilities: Weaknesses in software or hardware can be exploited by attackers.
•	Weak security controls: Poor passwords or inadequate access control make it easier for attackers to get in.

External threats originate outside your organization:
•	Cybercriminals: They use various methods (malware, phishing, denial-of-service) for financial gain, espionage, or just the challenge.
•	Competitors: They may resort to unethical means (stealing trade secrets, website attacks) to gain an advantage.
•	Hacktivists: These are individuals or groups using technology to push a political or social agenda, sometimes launching attacks against organizations they believe are wrongdoers.
•	Nation-states: They may attack for espionage or to disrupt critical infrastructure, often having the resources for sophisticated attacks.
By understanding these threats, you can take steps to protect your organization:
•	Implement a cybersecurity framework to identify, manage risks, and respond to incidents.
•	Educate employees on cybersecurity best practices to spot phishing and create strong passwords.
•	Use strong security controls like firewalls, intrusion detection systems, and encryption.
•	Monitor your systems and networks for suspicious activity.
•	Have a plan in place for responding to security incidents.


Why internal threats are more damaging than external threats?
Internal threats are often more successful than external threats because:
•	Familiarity Breeds Complacency: People become accustomed to seeing insiders around, potentially overlooking suspicious behaviour.
•	Greater Access: Insiders have legitimate access to systems and data, allowing them to bypass security measures more easily.
The cost of insider incidents can be higher due to:
•	Deeper Access: Insiders can steal or damage more sensitive data.
•	Loss of Trust: Insider breaches can damage an organization's reputation and customer trust.

## Denial of Service (DoS) Attack in Azure

- **Security Solution**: Use Azure Application Gateway with Web Application Firewall (WAF); leverage rate limiting and auto-scaling
  for services.
- **Detection**: Monitor metrics with Azure Monitor and Log Analytics for high CPU, memory, or failed requests.
- **Mitigation**: Deploy traffic throttling, enable WAF rules, and autoscale app services or VMs.
- **Examples**: Overloading an Azure App Service with repeated login attempts.

## **2. Distributed Denial of Service (DDoS) in Azure**

- **Security Solution**: Azure DDoS Protection Standard with Virtual Network (VNet) integration.
- **Detection**: Alerts via Azure Security Center and traffic patterns in Network Watcher.
- **Mitigation**: Geo-filtering, rate limits, and DDoS mitigation policies; integrate with Azure Front Door.
- **Examples**: Botnet attack targeting an Azure-hosted API endpoint.

## **3. Man-in-the-Middle (MitM) Attack**

- **Security Solution**: Enforce HTTPS/TLS 1.2+, use Azure Key Vault for certificate management.
- **Detection**: Monitor for abnormal TLS certificate changes or MITM indicators in Defender for Cloud.
- **Mitigation**: Enforce secure transport (HTTPS), disable legacy protocols, and use ExpressRoute or VPNs for private links.
- **Examples**: Interception of traffic between Azure VMs and external services via compromised proxy.

## **4. Packet Sniffing in Azure**

- **Security Solution**: Encrypt data in transit using TLS; isolate VNets and use private endpoints.
- **Detection**: Monitor for unauthorized NSG or route changes, enable Azure NSG flow logs.
- **Mitigation**: Implement strict NSG rules, disable promiscuous mode in NICs.
- **Examples**: Internal VM trying to sniff traffic on a flat subnet without segmentation.

## **5. Port Scanning in Azure**

- **Security Solution**: Use Just-In-Time (JIT) VM access, NSG and Azure Firewall rules.
- **Detection**: Enable Azure Defender alerts for scanning behavior; analyze NSG flow logs.
- **Mitigation**: Block unused ports, apply IP restrictions, use JIT access control.
- **Examples**: External attacker scanning Azure VMs for exposed RDP/SSH ports.

## **6. SQL Injection in Azure**

- **Security Solution**: Use parameterized queries, stored procedures; Azure WAF SQLi detection rules.
- **Detection**: Monitor Azure SQL Database Threat Detection logs and Defender for SQL alerts.
- **Mitigation**: Input sanitization, WAF rules, application-level validation.
- **Examples**: Injecting SQL commands into a vulnerable Azure-hosted web app form.

## **7. Cross-site Scripting (XSS) in Azure**

- **Security Solution**: Use Azure WAF with XSS protection, validate user inputs on front and backend.
- **Detection**: Defender for App Service alerts, App Insights traces for suspicious script activity.
- **Mitigation**: Output encoding, CSP headers, DOM sanitization.
- **Examples**: Injecting malicious JavaScript into an Azure Static Web App.

## **8. Cross-Site Request Forgery (CSRF) in Azure**

- **Security Solution**: Use anti-CSRF tokens in Azure Web Apps, secure cookies.
- **Detection**: Monitor application behavior for unauthorized changes or CSRF patterns.
- **Mitigation**: Enforce SameSite cookies, validate origin headers, implement user session integrity.
- **Examples**: Unauthorized form submission in Azure-hosted apps via forged requests.

## **9. Phishing Attacks in Azure**

- **Security Solution**: Use Microsoft Defender for Office 365, multi-factor authentication (MFA) via Entra ID.
- **Detection**: Phishing campaign indicators through email tracing and alerting in Microsoft Defender.
- **Mitigation**: Conditional Access Policies, user training, phishing simulations.
- **Examples**: Phishing email targeting Azure admins to harvest credentials.

## **10. DNS Spoofing / Cache Poisoning**

- **Security Solution**: Use Azure DNS with DNSSEC (if supported externally); private DNS zones.
- **Detection**: Monitor DNS traffic with Azure Firewall logs and Sentinel analytics.
- **Mitigation**: Enforce encrypted DNS (DNS over HTTPS), configure secure forwarding rules.
- **Examples**: Tampering with DNS records to redirect Azure-hosted services.

## **11. Eavesdropping**

- **Security Solution**: TLS encryption for all data in transit; use ExpressRoute or VPN for private comms.
- **Detection**: Look for unusual traffic on monitoring tools like Network Watcher.
- **Mitigation**: Avoid public endpoints, enforce TLS 1.2+, and secure internal traffic paths.
- **Examples**: Intercepting unencrypted API traffic between Azure resources.

## **12. Zero-Day Exploits in Azure**

- **Security Solution**: Enable Microsoft Defender for Cloud with threat intelligence and EDR.
- **Detection**: Use Azure Sentinel for anomaly detection; patch validation monitoring.
- **Mitigation**: Regular updates via Azure Update Manager, least privilege enforcement.
- **Examples**: Exploiting an unpatched vulnerability in Azure Function runtime.
