# Threat Hunting Guide

## Introduction

Threat hunting is a **proactive cybersecurity practice** that focuses on identifying malicious activity that has bypassed traditional security controls such as firewalls, antivirus solutions, Endpoint Detection and Response (EDR), and Security Information and Event Management (SIEM) alerts.

Unlike traditional security monitoring, which reacts to alerts generated by automated systems, threat hunting assumes that attackers may already be present within the environment and actively searches for indicators of compromise (IoCs), attacker behaviors, and anomalies.

In Microsoft Sentinel, threat hunting primarily involves analyzing security telemetry using **Kusto Query Language (KQL)** to identify suspicious activities across Azure, Microsoft 365, Microsoft Defender XDR, Microsoft Entra ID, and other connected data sources.

---

# What is Threat Hunting?

Threat hunting is the process of:

- Proactively searching security logs for hidden threats
- Investigating suspicious user and system behavior
- Identifying attacker techniques before major incidents occur
- Reducing dwell time by discovering threats early
- Improving organizational security posture

Threat hunters combine:

- Threat intelligence
- Security analytics
- Behavioral analysis
- MITRE ATT&CK framework
- KQL queries
- Human expertise

---

# Objectives of Threat Hunting

The primary objectives are to:

- Detect threats that evade automated security controls
- Identify insider threats
- Detect compromised identities
- Discover malware persistence
- Investigate lateral movement
- Identify privilege escalation
- Detect data exfiltration attempts
- Improve detection rules
- Strengthen incident response

# Threat Hunting Lifecycle

## Stage 1 — Before an Incident (Proactive Hunting)

This is the preferred stage where security teams actively search for hidden threats before attackers can achieve their objectives.

Activities include:

- User behavior analysis
- Identity monitoring
- Network traffic analysis
- Endpoint investigation
- Running custom KQL queries
- Threat intelligence correlation
- Vulnerability analysis

---

## Stage 2 — During an Incident (Active Investigation)

Once an attack has been detected, threat hunting helps determine:

- Scope of compromise
- Initial attack vector
- Impacted systems
- Lateral movement
- Persistence mechanisms
- Privilege escalation
- Data accessed

Activities include:

- Log correlation
- Timeline analysis
- Live investigation
- Hunting for additional compromised systems
- Root cause analysis

---

## Stage 3 — After an Incident (Post-Incident Hunting)

After containment, organizations perform retrospective hunting to improve security.

Activities include:

- Validate complete attacker removal
- Review missed detections
- Improve analytics rules
- Update hunting queries
- Update threat intelligence
- Improve security controls
- Conduct lessons learned

---

# Threat Hunting Methodologies

## 1. Hypothesis-Driven Hunting

Threat hunters begin with a hypothesis based on attacker behaviors.

Example:

> "An attacker may be using PowerShell to download malware."

The hypothesis is validated using KQL queries and endpoint telemetry.

---

## 2. Intelligence-Driven Hunting

Threat hunters use:

- Threat intelligence feeds
- Known Indicators of Compromise (IoCs)
- MITRE ATT&CK techniques
- Known malicious IP addresses
- Malicious domains
- File hashes

to search for attacker activity.

---

## 3. Analytics-Driven Hunting

Uses:

- Machine Learning
- UEBA
- Microsoft Defender XDR
- Microsoft Sentinel Analytics
- AI-assisted detections

to identify anomalies automatically.

---

## 4. IOC-Based Hunting

Searches for known indicators including:

- IP addresses
- Domains
- URLs
- File hashes
- Registry keys
- Process names
- Email addresses

---

## 5. Anomaly-Based Hunting

Focuses on abnormal behavior instead of known signatures.

Examples include:

- Impossible travel
- Login at unusual hours
- Unusual Azure resource deployment
- Sudden privilege elevation
- Excessive failed logins
- Unexpected data transfers

---

# Threat Hunting vs Threat Detection

| Feature | Threat Hunting | Threat Detection |
|----------|---------------|------------------|
| Approach | Proactive | Reactive |
| Trigger | Analyst hypothesis | Security alert |
| Goal | Discover unknown threats | Detect known threats |
| Execution | Manual + Automated | Mostly Automated |
| Focus | Unknown attacker behavior | Known attack signatures |
| Human involvement | High | Moderate |
| Detection capability | Advanced threats | Known threats |

---

# Threat Hunting vs Other Security Technologies

| Technology | Purpose | Benefits | Limitations |
|------------|----------|----------|-------------|
| Threat Hunting | Proactively searches for hidden threats | Detects advanced attacks | Requires expertise |
| SIEM | Centralized log collection and analytics | Correlates security events | Requires tuning |
| IDS/IPS | Detects and blocks known attacks | Real-time protection | Signature dependent |
| EDR | Endpoint monitoring and response | Endpoint visibility | Limited to endpoint data |
| Vulnerability Scanner | Identifies vulnerabilities | Reduces attack surface | Does not detect active attacks |

# Conclusion

Threat hunting is an essential component of a modern Security Operations Center (SOC). By proactively searching for indicators of compromise, suspicious behaviors, and attacker techniques, organizations can detect threats that automated security tools may miss.

Microsoft Sentinel provides powerful capabilities—including KQL, Hunting Queries, Bookmarks, Live Stream, UEBA, Notebooks, and Threat Intelligence integration—that enable security analysts to conduct effective threat hunting across cloud and hybrid environments.

A mature threat hunting program significantly improves an organization's ability to detect advanced threats, reduce attacker dwell time, strengthen incident response, and continuously enhance its overall cybersecurity posture.
